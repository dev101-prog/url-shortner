# Scenario B2: expired link served from the cache returns 404 instead of 410 (brownfield bug fix)

Branches: `demo/b2-seeded-bug` (defect + failing regression tests, from `main`) and
`fix/b2-expired-cache-410` (the fix, from `demo/b2-seeded-bug`). Neither is merged.

## Ticket
URL-SCN-B2 / URL-FR-3.2 / URL-FR-4.3: expired links must return 410, including when served from
the cache. The greenfield code on `main` is correct; the defect is seeded on purpose (design §11.3).

## Seeded defect
`scripts/demo/b2-seeded-bug.patch` (`git apply scripts/demo/b2-seeded-bug.patch`; applies cleanly
to `main`) adds `CachedLink.isExpired(now)`, a second copy of the status rule, and this cache-hit
branch in `RedirectService`:
```java
// BUGGY (seeded): cache-hit path collapses EXPIRED into NOT_FOUND
if (cached.status() == LinkStatus.INACTIVE || cached.isExpired(now)) {
  return new RedirectResult.NotFound();
}
```

## Reproduction (regression tests written first)
- `RedirectServiceTest.b2_expiredFromCacheReturnsGone` (unit): a cache hit for an expired link
  must be `Gone`.
- `B2ExpiredFromCacheIT.b2_expiredLinkIs410FromDbAndFromCache` (the curl reproduction on
  Tomcat + Postgres): the first request is a DB miss and returns 410, then the entry is cached;
  the second request is a cache hit and must also return 410.

## AI interaction summary
- Hypotheses the AI ranked from the failing curl output (410 then 404 for the same code): (1) the
  cache-hit path evaluates status differently from the DB path (most likely, because the first
  request is served from the DB and the second from the cache); (2) the negative cache wrongly
  marks the code missing; (3) the cache stores a stale INACTIVE status.
- (2) was ruled out because the DB path back-fills the positive cache, not the negative one.
  (3) was ruled out because the row is ACTIVE.
- The engineer confirmed (1) by reading the cache-hit branch.

## Root cause (recorded for the fix PR)
**Duplicated status logic in two branches**: the cache-hit path had its own `INACTIVE || isExpired`
check mapped to NOT_FOUND instead of using the single `EffectiveStatus.evaluate` rule used by the
DB path.

## Fix (on `fix/b2-expired-cache-410`)
Route both paths through one evaluator (`CachedLink.effectiveStatus(now)` ->
`EffectiveStatus.evaluate`) and delete `CachedLink.isExpired` (the reverse of the seeded patch:
`git apply -R scripts/demo/b2-seeded-bug.patch`). The fixed hot path is the design's "fixed code":
```java
Instant now = clock.instant();
return switch (link.effectiveStatus(now)) {   // one rule for cache hits and DB reads
  case INACTIVE -> new RedirectResult.NotFound();
  case EXPIRED -> new RedirectResult.Gone();
  case ACTIVE -> { recordClick(...); yield new RedirectResult.Found(link.targetUrl()); }
};
```
