# Scenario B3: extract `CodeGenerator` (brownfield refactor)

Branch: `refactor/b3-code-generator` (from `main`; not merged)

## Ticket
URL-SCN-B3 (design §11.3): move code generation behind a `CodeGenerator` interface with no
behaviour change, so later strategies (sequence + Hashids, pre-generated pools) need no service
changes.

## AI interaction summary
The AI drafted the behaviour-preserving change under the rule "do not change public signatures,
the OpenAPI baseline or tests":
- `service.port.CodeGenerator` with `String next()`.
- `infra.RandomBase62CodeGenerator(SecureRandom, length)`: the same alphabet and
  `random.nextInt(62)` loop that was inside `LinkService`. The bean is built in
  `config.RandomConfig` so infra still never imports config (ArchUnit rule 4).
- `LinkService` depends on `CodeGenerator` instead of `SecureRandom` and the code length.
  Retry, exhaustion and metrics logic are unchanged.
- Tests: `LinkServiceTest` constructs the service with the real generator; per §11.3 the two
  collision tests now use a stub `CodeGenerator` returning fixed codes (simpler and
  deterministic). New `RandomBase62CodeGeneratorTest` (alphabet mapping, length, 1,000 draws
  without collision).
